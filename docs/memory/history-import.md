# History imports and background jobs

ADN and Netflix history imports, background job store. Part of the project memory (`CLAUDE.md` › Project memory).

- **ADN history import** (same page and pipeline as the Crunchyroll import, `import-cr/` kept as folder name, `Cr*` names / `crImport:*` keys / `CR_IMPORT_*` messages shared, `platform` on the payload, input and plan, absent = Crunchyroll): the content script of the ADN tab (`content/adn/history.ts`) calls `GET gw.api.animationdigitalnetwork.com/viewing/history?offset=…&limit=100&onlyNext=false` (`limit` ≤ 100, 500 → HTTP 400; `onlyNext` changed nothing on a 13-entry history) with exactly the site's headers (`authorization: Bearer`, `x-profile-id`, `x-target-distribution`, `accept-language`, `x-i18n-platform: 1`, `x-source: Web`), `credentials: 'omit'` (cookies or extra headers break the CORS request). Token read from the page `localStorage['token']` at each read, never `refresh_token`; it never leaves the tab (never logged, stored or put on the port; fixtures use a fake JWT). Fetch through `pageFetch()` (`content.fetch` on Firefox: page origin, as on Chrome). 401/403 → « connecte-toi puis recharge la page ADN ». Only picked episode fields go through the port (`synckai:adn-history`); the import page reduces them (`platforms/adn/history.ts`, never in the content bundle): watched = `isFullyWatched` or `stoptime/duration` ≥ `completionPercentage`, one row per (show, season). The « watched » rule and the per-season reducer are shared by the three platforms (`shared/history-source.ts` › `isEpisodeWatched` / `reduceWatchEvents` on `WatchEvent`s: each source picks its season key, rank and units; content-safe, the Crunchyroll reader reduces in the tab), and `decideImport` shares the list rule of live sync (`shared/list-update.ts` › `progressStep` / `reachesLastEpisode`, audit 1-D14), `shortNumber` as season and displayed number (like the live JSON-LD), no genre filter. On-demand readers (`perf/history-on-demand`, Crunchyroll and ADN): the readers are not in the manifest content script but in `content/history/history.iife.ts` (CR or ADN port listener by hostname, guard `claimContentInstance(Symbol.for('synckai.history'))`), injected by the import page before each port attempt (`import-cr/history-reader.ts`, the only `?script` import outside `platform-access.ts`: `scripting.executeScript({ files })`, isolated world; failure → same retry / « recharge l'onglet » path as a silent port). Never exposed to sites: `dropExtensionInjectedScripts` (`src/build/output-names.ts`) removes it from `web_accessible_resources`, `checkWebAccessibleResources` refuses it there; budget `HISTORY_READER_BUDGET_BYTES` 16 KB (15.3 KB since the shared reducer). The import page chunk has a fixed name (`assets/import-cr.js`, like the service worker): crxjs's `?script` placeholder depends on the project folder. ADN is in `host_permissions` (same hosts as the content-script matches, so no new install warning): without it Chrome/Brave hide the URL of ADN tabs from `chrome.tabs.query({ url })` (content-script matches let `permissions.contains` answer true but do not reveal tab URLs), and the import page never found the ADN tab (2026-10-12). `docs/store/permissions.md` (data disclosure, ADN matches) changed: paste its blocks in the Privacy tab before the next tag.
- **Netflix history import** (same page and pipeline, `ImportPlatform` `netflix`, `?platform=netflix`): the import page drives the user's Netflix tab on `netflix.com/viewingactivity` itself with `chrome.scripting.executeScript` (one self-contained function `netflixTabOp` in `platforms/netflix/tab-op.ts` (no import, checked by `tab-op.test.ts`): no reference outside its body, it is serialized; ops `state` / `click` / `rows` / `show`), so the content bundle only gained the bridge's bookmark request (+0.6 KB, 62.3 → 62.9 KB of 65 KB; a port-based reader in the content script cost +3.5 KB and was dropped). The function runs in the extension's isolated world, the one of the Netflix content script, which exposes `loadHistory` under `Symbol.for(NETFLIX_HISTORY_HOOK)`; 'absent' = no content script (reload the tab). Never click anything but the site's « Voir plus » button outside `li.retableRow` (never « Masquer dans l'historique », « Signaler un problème »). It is found by its text, in the language of the Netflix PROFILE (not SyncKai's), compared lowercased in NFC; the list holds verified labels only: FR / EN / DE seen on the site, it, es / es-419, pt-BR, nl, sv, pl, cs, ro, ru (еще / ещё), uk, tr, id, vi, ja, zh-TW from Netflix's help article (help.netflix.com/<lang>/node/101917, checked by each translator or reviewer, 2026-10-14), zh-CN « 显示更多 » and ko « 더 보기 » from the same article (2026-10-14): every SyncKai language is covered. Any other profile language (Thai, Arabic…) never finds the button: no click and a full first page (≥ `NETFLIX_PAGE_ROWS` = 20 rows) → `moreUnrecognized` (and `partial`), carried in `HistoryStats.moreUnrecognized`, notice `crImport.netflix.moreUnrecognized` (set the Netflix profile to SyncKai's language) instead of `crImport.read.partial`; a history of exactly 20 rows gives the same notice (indistinguishable). The site's Falcor request (`pathEvaluator`, needs `authURL`) is never replicated. Loop (`readNetflixHistory`, pure): wait for rows (15 s), click while the button exists, ≥ 1 s between clicks, wait ≤ 8 s for new rows, stop after 3 clicks without growth / 400 clicks / 6000 rows (partial), « Arrêter » checked before each click. Rows = `{ id (/title/{id}: episode id, title id for films), text }`; title split on the last `: "…"` (episode in quotes of any language: « » „ “ ” ‚ ‘ ’ " 「 」 『 』 ‹ ›, opening or closing; NBSP before « : »; full-width « ： » also accepted, CJK row format unverified) then the last « : » (season) ; grouped by normalized series title (3 ids kept). Request budget: AniList filter by distinct title in the background lane, `NETFLIX_TITLES_PER_REQUEST` = 10 searches per GraphQL request with aliases (`searchAnimeBatch`, same fields / perPage 20 / cache keys as `searchAnime`; complexity 35 per search since the matching signals, AniList max 500 → 14 max; one constant `ANILIST_SEARCHES_PER_REQUEST` in `shared/anilist.types.ts`, also `MAX_SEARCH_BATCH`), message `NETFLIX_IMPORT_TITLES`; kept if a found entry links to a Netflix `/title/{id}` or has the exact title; then ONE metadata request per kept title (`loadHistory`, `bookmarks: true`, 700 ms apart, never cached, a null after ≥ 20 s = silent bridge → « recharge l'onglet »), show kept if its `showId` is linked or title matched (`keepsShow`), else counted in `stats.ignored` (titles, never logged). ~300 titles ≈ 30 AniList requests (~1.5 min at 20 background/min, ~40 s at 45) + one Netflix request per anime + the usual analysis. Watched (`isNetflixWatched`): `bookmark.offset ≥ min(watchedToEndOffset, creditsOffset)` (missing / ≤ 0 ignored), else `completionPercentage` of runtime; Netflix keeps only the LAST bookmark, so per season progress = highest watched `seq` (Ranma ½ S1 → 5, E6 1262 < 1283). `reduceNetflixShow` uses the live numbering (`episodeNumbers`, `platformSeasonsOf`, `meaningfulSeasonTitle`, moved to `platforms/netflix/metadata.ts` / `shared/title.ts`) and `HistorySeason.platformSeasons`, so `toEpisodeInfo` equals the live `episodeInfoFromMetadata` (parity test `content/netflix/import-parity.test.ts`). The resolver's `ignored` verdict becomes `SeasonResolution` `ignored` (plan `ignored`, « N titres ignorés (pas des animes) »); title-only → « À vérifier », as live. Bridge protocol v2 (`NETFLIX_BRIDGE_VERSION` 2): request `bookmarks: true` → episodes (film: show) get `bookmark: { offset, watchedToEndOffset } | null` (watchedDate dropped); live sync never asks for it. Access: Netflix optional → the import page uses `hasPlatformAccess` / `requestPlatformAccess('netflix')` (same permission as the Settings toggle, `permissions.onAdded` registers and injects the scripts). Untested on the real site: films (`bookmark` at the video level), the empty-history container `.retable`, the profile gate selectors, Firefox's shared isolated world between `executeScript` and registered content scripts. `docs/store/permissions.md` (scripting, Netflix host, host block, data disclosure) and `PRIVACY.md` changed: paste the changed blocks in the Privacy tab before the next tag.
- **Background jobs** (`background/jobs/runner.ts`, PERF-16, `perf/job-store`, 2026-10-16): a job's items live in `<job key>:items` (`compare:job:items`, `crImport:job:items`), written once by `reserveJob` and removed with the job; the job itself keeps `cursor` (next item), `itemCount` and `current` (item shown by the page, set at item start and moved to the next item when one ends, never null in between), so every rewrite (item, heartbeat, pause) stays a few hundred bytes. A job stored by an earlier version (`pending[]` inside, no `cursor`) is converted on read by the service worker (`fromLegacyJob`) and written in the new shape at its first locked update; pages read it as « no job » until then (a few seconds after `onInstalled`). Reloading the extension during the history READING (« Vérification de la numérotation : x / y saisons », page-driven, before any job exists) loses the reading: expected, start again.
