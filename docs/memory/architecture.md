# Module boundaries

Full rules of the module boundaries, enforced by `src/architecture.test.ts` (type imports included). Part of the project memory (`CLAUDE.md` › Project memory).

- **No import cycles.** A constant shared by two modules that import each other goes into a leaf module (e.g. `protocol/storage-keys.ts`, `shared/title.ts`).
- **Layers** (folders of `src/`): `shared/` (pure domain: types, guards, rules, no browser API call), `protocol/` (contracts between runtimes: `messages`, `content-messages`, `live`, `panel-toggle`, `commands`, `adn-history`, `netflix-history`, `storage-keys`), `platforms/` (what SyncKai knows about each platform, safe for the MAIN world: `ids`, `registry`, `target-pages`, `links`, `<platform>/metadata`, `<platform>/history`, `netflix/tab-op`), `browser/` (everything that calls `chrome.*`: `storage/`, `tokens/`, `badge`, `side-panel`, `platform-access`, `host-access`, `airing-alarm`, `logger`, `error-journal`), then `background/`, `content/`, `ui/` and the screens. `shared/`, `platforms/`, `protocol/` and `browser/` never depend on `ui/`, `popup/`, `sidepanel/`, `content/`, `background/`, `import/`, `import-cr/`. `shared/` calls no browser API (test); its few remaining imports of `browser/` (and `i18n/core`'s) are a frozen list that only shrinks. `chrome.storage.local` keys live in `protocol/storage-keys.ts`; the lock in `browser/storage/lock.ts`.
- **MAIN-world bridges** (`content/<p>/page-bridge.iife.ts`) reach only their own `bridge-protocol.ts`, `platforms/<p>/`, the bridge kit `content/bridge/kit.ts` and `shared/{guards,hosts,lru,match-signals,title}.ts`, and none of those modules contains `chrome.` (tests). Every bridge goes through the kit (Template Method, `refactor/bridge-kit`, 2026-10-16): `installPassiveBridge` (Crunchyroll, Disney+, Prime Video: fetch / XHR wrapped ONCE per platform under a version-less `observerKey` slot that a newer version re-injected after an update only swaps, 2-R3; responses re-parsed into objects without prototype, so a polluted `Object.prototype` feeds nothing, SEC-05; 4 ports max) or `installActiveBridge` (Netflix); a bridge supplies only `observe`, `onPayload` (returns the message to broadcast) and `snapshot`. The slot's shape (`{ current: { match(url) → { maxLength, read(body) } | null } }`, final since `fix/content-robustness`, never released before) is a contract between versions: changing it needs a new key. Fetch bodies are read as a stream and dropped as soon as they pass the bridge's byte cap (2-R13), XHR texts by length. Isolated clients use `content/bridge/client-kit.ts` (`createBridgeConnection`: first trusted port offered for a nonce, retried after a timeout; `createWaiters`: every wait has a MANDATORY timeout, 2-R11; `untilAborted`, `lazy`). What crosses a bridge is page-authored data: the nonce is readable by the page and `isTrusted` is also true for the page's own `postMessage`; the real guarantee is ordering (bridge listener installed at `document_start`), weaker for a bridge re-injected into an open tab; clients revalidate everything and bridge data is never the sole proof of a match. `scripts/verify-build.ts` also refuses `chrome.`, header, cookie and storage accesses in the built bridges, and dev-build markers (`debug:matchDiagnostic`, `[disney]`) anywhere in the package.
- **Tokens**: `browser/tokens/access.ts` (decryption) is imported by `background/` only, and no page or content script reaches it (test, no exception since `fix/token-boundary`, SEC-06): the diagnostics report is built and redacted in the service worker (`GET_DIAGNOSTICS_REPORT`, origin `extension`, `background/diagnostics-report.ts` passes `readTokenSecrets()` to `browser/storage/diagnostics-store.ts` › `buildCurrentReport`); *Settings › Help & about* only receives the finished text.
- **Service worker wake-ups**: the number of `addListener` calls per browser event in `background/` is frozen (test); a new listener is a decision, not a side effect. No `storage.onChanged` listener in `background/` (test, PERF-17, 2026-10-15: it woke the worker on every local write), nor one registered for the worker by a shared module: `initI18n` in follow mode registers `storage.local.onChanged` after an `await`, and Chrome still keeps it as a lazy listener (measured 2026-10-15 by `scripts/ext-e2e/worker-wake.ext.ts`: a page's local write started the stopped worker, a `storage.session` write did not), so `background.ts` calls `initI18n({ follow: false })` and re-reads the language before each piece of work (see Known pitfalls › i18n). The airing alarm is kept in sync by `browser/airing-alarm.ts` › `ensureAiringAlarm`, called where its conditions change (`updateSettings` and `applyBackup` in the pages, sign-in in `background/{anilist,mal}/auth.ts`, `session-end.ts` › `afterSessionEnd`, `onInstalled` / `onStartup`, « Check now ») and by the alarm handler when the check is skipped (`disabled` / `not-connected`). Listing storage keys goes through `browser/storage/stored-keys.ts` (`getKeys` when present, else `get(null)`; PERF-14). `getKeys` checked present on the owner's Chrome and Firefox (2026-10-15); the `get(null)` fallback remains for Firefox versions without it (the first version that has it is unconfirmed).
- **`ui/`**: shared interface kit (`kit.ts`, `feedback.ts`, `state.ts`, `media-action-requests.ts`, `page-exclusion.ts`, `settings/`…), never `popup/` or `sidepanel/`. Extension pages move to Preact screen by screen (decision 12, rules in `docs/design/README.md` › Preact): `.tsx` only there, no `preact/compat` / React nor `dangerouslySetInnerHTML` (ESLint), hooks in `ui/preact/`, shared components in `ui/components/` (list in the design charter; dev gallery: `node scripts/screenshots/gallery.ts`), every mounted tree unmounted on dispose, content scripts and content-safe modules vanilla; popup and panel load the Settings view with a dynamic `import()` at first open (Preact itself is in their initial load since the status bar). Settings (`ui/settings/`, Preact since `feature/ui-settings`): shell `settings-view.tsx` (bar, home, focus and scroll on navigation), page tree in `navigation.ts` (home › Accounts, Sync › Matches / Excluded series, Platforms, Notifications, Display › Language / Shortcuts, My data › AniList ↔ MAL differences, Help & about; `settingsPath` builds the « Settings › … » paths quoted by other texts), one `SettingsMountedPage` per page (`preactPage`, mounted on open, unmounted when left), page data through `useStore(ctx.state)`; no vanilla page remains. The AniList ↔ MAL comparison lives in *Settings › My data › AniList ↔ MAL differences* (`page-compare.tsx`, pure rules in `compare-model.ts`), driven by `ui/compare-controller.ts`: one per host page (`SettingsHost.compare`; the popup creates it at boot for its Activité row, which only links to that page with the count of differences; the panel at first use). A component used by two screens (popup, panel, settings, import pages) moves up into it. « Pour toi »: the `Discover` view (`ui/components/discover.tsx`, moved from `sidepanel/components/` in `d6a7145`) and `ui/reco-controller.ts` (one per page, created at the first display of the panel's Discover tab or of the popup's « Pour toi » section; the popup passes the remembered `RecoFilter`, the panel none) serve both screens; the popup wraps it in `popup/components/foryou-screen.tsx` (genre and format filters), the filter being kept in `popupPrefs:sections` (`popup/controllers/section-prefs.ts`). Content scripts import only `ui/{rating,star-rating,kai-small,svg}.ts` (test). Optional-platform access (Netflix, Disney+, Prime Video): ONE `ui/platform-access-store.ts` › `createPlatformAccessStore()` per page (popup, panel), created at boot and passed to the page-media controller, `sidepanel/presence.ts`, the Settings view (`SettingsHost.platformAccess`, mirrored in `SettingsData.platformAccess`: an array, no per-platform boolean), the Agenda and the now-playing controller; it holds the page's only `permissions.onAdded` / `onRemoved` pair (test in `architecture.test.ts`), the latest re-read wins (4-R2), `read()` waits for a re-read in flight, `onPermissionsChange` fires on every permission event (host access included). Enable buttons and the Settings toggle call `requestPlatformAccessFromClick(platform, store)` (request sent synchronously in the click, then the store re-read). The import page keeps its own on-demand `hasPlatformAccess` / `requestPlatformAccess` (single source, no listener). Controllers without DOM, unit-tested: `ui/page-media-controller.ts` (with `ui/redetect-limiter.ts` and `ui/tab-cache-echo.ts`), `ui/agenda-controller.ts` (week data and request budget: ‹ › debounced 300 ms, a week chosen in the calendar loaded at once, weeks received kept for the page's lifetime and shown again without a request while they pass the storage cache's rule (`isWeekCacheFresh`: 1 h for the current week, 6 h for a coming one, 7 days for a past one read after its end; the 60 s refetch guard still applies, PNL-02), an answer for a week left during a ‹ › burst kept but not shown (PNL-03); `ui/components/agenda.tsx` keeps the rendering, the « ⋯ » menu and the delay editor; both moved from `sidepanel/` in `5f165f3` because the popup's « Agenda » section mounts them too: `popup.ts` creates the controller at the first display of the section (`activate()` on every display, `dispose()` on `pagehide`), the panel at its first Agenda tab; `inset` and `visible` props, `data-scroll-root` on the host's scroll area; the month calendar is `ui/components/week-picker.tsx`), `ui/status-bar-model.ts` (pure: state priority, unseen syncs, account logos) and `ui/status-bar-source.ts` (storage reads and `storage.onChanged`, seen marks `statusBar:syncsSeenAt` / `statusBar:importSeenAt` in local) behind the status bar shared by popup and panel (`ui/status-bar-host.tsx` › `mountStatusBar`; panel → popup Activité through `browser/popup-screen.ts`, a running alignment → Settings › My data › AniList ↔ MAL differences (`openCompare`), « Synchro… » from `browser/storage/sync-activity.ts` in `storage.session`; its account logos open `ui/account-menu.tsx`, rules in `ui/account-menu-model.ts`); the page-media and now-playing controllers, accounts, the Settings view and the Agenda expose `dispose()` (4-R6: hosts create each once per page today, a host that recreates one must dispose the old one).
- **`popup/`, `sidepanel/`, `import/`, `import-cr/`**: standalone screens, which depend on `ui/` and `shared/` without importing each other; their only edge to `content/` is the `?script` import of `import-cr/history-reader.ts` (history readers, test). The popup has no vanilla part left (`feature/ui-popup-page-activity`): shell `popup-app.tsx`, « Mes séries » (`components/watching-screen.tsx`), « Sur cette page » (`components/page-media-card.tsx`, its parts in `ui/components/`) and Activité (`components/activity-screen.tsx`; the « À vérifier » card and section in `ui/review-card.tsx`, rules in `ui/review-view.ts`, ready for the panel), all reading the render-free controllers (`popup/controllers/{watching,queue,ratings}.ts`, `ui/page-media-controller.ts`) through `useStore`; `ElementSlot` remains only for the Settings view and the status bar container. The side panel has none left either (`feature/ui-sidepanel`): shell `panel-app.tsx` (state and logic in `sidepanel.ts`), « En lecture » (`components/{now-playing,now-playing-hero,live-card,list-card,details-card,off-target}.tsx` over `components/now-playing-controller.ts` and the render-free `components/live-progress.ts`: retries at +0.8 s and +2 s, then « unreachable » until the same tab is signalled again, `setTab` re-following it so a reload gives three more tries, PNL-01; the watch order's list states stay in that controller for the panel page's lifetime, decision 7 (a) of the 2026-11-10 audit, PERF-03 / ORD-06: read again on a franchise change, on « Actualiser » and after a panel list action (both `fresh`), the shown entry's row patched from its re-resolved « Ta liste » after a popup action or a sync, no `GET_LIST_STATES` under 2 entries; « Dans le même esprit » filters once per media, RECO-07; the worker's 5 min MAL list memo in `background/franchise/states.ts` only groups simultaneous reads and is forgotten on any MAL write through the entry generation) and the Agenda (`components/agenda.tsx` over `agenda-controller.ts`), published to the tree as store snapshots. The import page reads each platform through a `HistorySource` (`import-cr/sources/source.ts`: tabs, access, `read(tabId, { signal, progress })` → done / failed / stopped; `crunchyroll.ts` and `adn.ts` over `port-reader.ts` (injection, port, retries), `netflix.ts` drives the tab); its logic lives in `import-cr.ts`, its state in `import-cr/state.ts` (published to the Preact tree of `import-cr/components/`: frame and steps 1–3 in `import-app.tsx`, `platform-choice.tsx`, `progress.tsx`, preview and import in `preview.tsx`), its display rules in `view.ts` and `preview.ts` (pure, tested). Settings › My data opens it without `?platform` (platform choice first). The Backup page (`import/`, Preact since `feature/ui-import-pages`): logic in `import.ts` (export / restore through `browser/storage/backup-store.ts`, unchanged), rules in `view.ts`, rendering in `components/backup-app.tsx`; both pages share `ui/components/page-header.tsx`.
- **`content/`** never imports `background/` (typed messages from `shared/` only).
- **`background/`** never imports `content/`, except the `?script` imports in `platform-access.ts`. Pure logic useful to both goes into `shared/` (e.g. `shared/page-media.ts`). Layout: `anilist/` and `mal/` (clients, auth, full lists), `trackers/` (adapters, `oauth-clients.ts`), `ports/` (`tracker.ts`, `catalog.ts`: the `Catalog` port read by the matching, default `anilist/catalog.ts`, injected as a default parameter so tests pass a fake), `jobs/`, `compare/`, `history-import/` (`cr-import.ts`: messages of the import page; `analyze.ts`, `apply.ts`, `import-job.ts`: job store and shared steps, `batch-writer.ts`: the write batch both jobs use; `netflix-import.ts`), `page-media/`, `sync/` (resolver, `candidates.ts`: candidate collection as pure steps over a `CandidateSet` — classify, settle, propagate, align — driven by the `candidateSteps` generator, queue…) with `sync/matching/` (`matching.ts`: season label, platform seasons alignment, single entry / whole show; `policies/<platform>.ts` + `policies/registry.ts`: one `PlatformMatchPolicy` per platform (AniList link shapes, own-page link, other series, Disney+ link settling, anime gate, presence), so HIDIVE = one more policy file; keys in `platforms/series-identity.ts`; `rules-engine.ts` + `stages/*.ts`: `resolveTarget`, ordered pure stages and one `finalize`; `judge.ts`: `judge()`, named doubts on the rules result shared by the sync (`syncResult` / `gateByPlatformLink`) and the series page (`page-media-rules.ts` › `pageMatchConfident`); `model.ts`, `mapping.ts`, `season-titles.ts`, `season-pool.ts`, `signal-groups.ts`, `concordance.ts`, `season-groups.ts`); `errors.ts`, `rate-limit.ts` and `entry-commands.ts` (guarded tracker writes) at the root. The layering between these folders is not enforced yet (several cross-imports remain).
- **Test seams**: every relative path in `vi.mock` / `vi.doMock` / `vi.importActual` must resolve to a file (test), so a move cannot leave a mock aiming at nothing.
- **`i18n/`**: the full catalogs (`i18n/index.ts`) never enter content scripts. Code reachable from them imports `i18n/content` (`content/` modules) or `i18n/core` (shared modules); every key it references goes into `i18n/content-keys.ts`, injected in English at build time through `define` (other locales: `GET_CONTENT_CATALOG`, see Known pitfalls › i18n; enforced by `src/i18n/content.test.ts`). The locale list lives in the leaf `i18n/locale-codes.ts`.
