# Testing and debugging

Dev builds, debug trace, e2e and real-extension tests. Part of the project memory (`CLAUDE.md` › Project memory).

- **Debugging**:
  - after reloading the extension, reopen the tab, otherwise the orphaned content script stays active;
  - automatic reload of dev builds (`chore/dev-auto-reload`, 2026-10-16): `npm run build:dev` writes `dev-build.json` (`{ stamp }`, the build's `__SYNCKAI_BUILD__`) at the root of the output folder in `closeBundle`, after every other file (`devBuildWitness` in `vite.config.ts`, `src/build/dev-reload.ts`); the running dev service worker keeps a 30 s alarm `debug:dev-reload` (created if absent, handled in the existing queue `onAlarm` listener, no new listener) that fetches it with `cache: 'no-store'` and calls `chrome.runtime.reload()` when the stamp differs (missing or unreadable file: nothing). Dev builds only: both strings are `DEV_ONLY_MARKERS`, the logger is created lazily so the published bundles are unchanged; the alarm wakes the dev worker every 30 s (keep it in mind when observing worker sleep on a dev build);
  - the content script prints its build timestamp in the console;
  - `npm run verify:build` refuses any packaged file that nothing references (crxjs builds each `*.iife.ts` again in the main build: `dropCrxIifeIntermediates` in `vite.config.ts` drops those chunks, `crxIifeIntermediates` in `src/build/output-names.ts`) and any font other than woff2 (`@font-face` declared in `src/ui/theme.css`, never the `@fontsource` CSS, which adds a `.woff` fallback); it also requires `THIRD_PARTY_NOTICES.txt` (`public/`, exempt from the unreferenced-file rule) to hold the `LICENSE` text of each `package.json` › `dependencies` entry, today Preact's MIT notice (`checkThirdPartyNotices`, audit ARCH-06; `scripts/build-checks.test.ts` checks the `public/` file without a build): a new runtime dependency adds its licence there;
  - dev builds (`npm run build:dev`, `npm run dev`) set the manifest `version_name` to « <version>-dev · <short sha> » (« + » when tracked files were modified), shown in `chrome://extensions` and the popup footer (`src/build/dev-version.ts`); production builds keep `version` only, so the published package is unchanged;
  - the service worker writes `[SyncKai:sync]` lines;
  - info/debug logs are visible only with `npm run build:dev` (or `npm run dev`); `npm run build`/`package` keep only warn/error;
  - debug trace (dev builds only, 2026-10-15): a chronological record of page → content script → service worker → AniList / MAL → popup / panel events (page, shortcut, sync, ui, account, alarm, log, network, message), read in *Settings › Help & about › Debug trace* (`ui/settings/debug-trace.tsx`, collapsed by default, filter by category, « Copy trace » = the whole trace as JSON to paste to the assistant, « Clear », verbose switch). Producers call `trace()` (`browser/debug-trace-client.ts`) under `if (__SYNCKAI_DEBUG__)`; pages and content scripts send the `debug:trace:message` message (outside `MessageMap` / `MESSAGE_ORIGINS` so it leaves published bundles; same-extension check, `clear` / `verbose` refused from content scripts), the service worker is the only writer (`background/debug-trace.ts`, one promise chain, batched) into `chrome.storage.session` (`debug:trace`, cleared when the browser closes): 300 events, 1000 in verbose mode, which also keeps every logger info/debug line (warn/error always kept). `shared/debug-trace.ts` bounds and filters every event (strings ≤ 200 chars, one nested level, ≤ 16 keys; keys about tokens, headers, cookies, sessions, accounts / profiles / viewers / users, URLs, bodies dropped; JWTs, Bearer values, secret URL params and long opaque strings redacted; URLs cut to their origin; comments as length only). `debug:trace` is a `DEV_ONLY_MARKERS` entry: `verify:build` refuses it in a published package; the production bundles are identical apart from identifier renaming (no new CSS class either). Not covered by `npm run test:ext` (it builds production);
  - end-to-end tests of the popup, the side panel, the import page and the Backup page: `npm run test:e2e` (Vitest + Puppeteer, headless Chrome; `scripts/e2e/`, panel records in `window.__e2ePanel`). The real popup runs on the mocked chrome API of the screenshots (`scripts/screenshots/mock-chrome.ts`); messages sent to the service worker, access requests and the clipboard are recorded in `window.__e2e`. CI `e2e` job; locally, Chrome via `npx puppeteer browsers install chrome-headless-shell` if missing.
  - real-extension tests: `npm run test:ext` (`scripts/ext-e2e/`, `vitest.ext.config.ts`, not in `verify`): builds `dist/`, copies it to a temp dir and loads it in a full Chromium (`SYNCKAI_EXT_CHROME`, default `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`; `chrome-headless-shell` cannot load extensions) with `pipe: true` (launch hangs without it), never puppeteer's `enableExtensions`. The service worker's network goes through the CDP `Fetch` domain (re-attached to each new worker) to stateful fakes (`fake-anilist.ts`, `fake-mal.ts`: token check, 500 / 429 / network errors on demand, latency); any other request is refused and recorded, DNS is off (`--host-resolver-rules`). `target.worker().evaluate()` hangs on the MV3 worker: `chrome.*` calls go through an extension page. Signed in without OAuth: legacy plaintext tokens seeded (the worker encrypts them). `EPISODE_COMPLETED` (content-only) is sent with `scripting.executeScript` from a faked Crunchyroll tab. `chrome.runtime.reload()` leaves a `--load-extension` extension unloaded: updates are tested by relaunching the same profile with a higher manifest version. Batch 1 (accounts, sync): 8 scenarios, ≈ 15 s. Batch 2 (`playback.ext.ts`, playback detection): 8 scenarios, ≈ 45 s; fake watch pages from the adapter fixtures (`fake-sites.ts`, `pageRoutes` / `openTab` of the harness) with a real `<video>` (`assets/episode-600s.webm`, VP8, 600 s, 22 KB, `data:` URL); completion driven by `play` + `seek` past the point (credits served as `static.crunchyroll.com/skip-events`, else 85 %); tracker state read on the live port `synckai:live` (connect retried until the content script is injected), toasts via CDP `DOM.getDocument({ pierce: true })` (closed Shadow DOM). Background tab: `openTab(url, { background: true })` (another tab in front, `visibilityState` hidden), player mounted on `visibilitychange`, the 30 s `VIDEO_WAIT_TIMEOUT_MS` really waited (`no-video` on the port). `Alt+Shift+K` cannot be pressed (CDP keys never reach `chrome.commands`): `FORCE_COMPLETE` sent to the tab from an extension page. The fake AniList finds nothing for an accented search (as the real one). Batch 3 (`panel.ext.ts`, `import.ext.ts`): 11 scenarios, ≈ 60 s (an extension update during an analysis whose job is in the pre-PERF-16 shape: `restart({ version })` after rewriting the stored job with `pending`). Side panel = its page `src/sidepanel/sidepanel.html` opened as a tab (`openPanel`) AFTER the bridge (any new tab becomes the active one): alone in front it follows itself (Agenda), then a platform tab opened in front is followed through `tabs.onActivated` / `onUpdated` (same code as the real panel); actions on the background panel tab via `$eval(el => el.click())` / `page.select`, texts via `innerText` (`textContent` includes `hidden` hints). Fake AniList also answers `PageMedia`, `PanelMedia`, `FullList` and the anonymous schedule query (named `AiringSchedules`, data in `anilist.airing`); seeds take `relations` / `startYear`. `fake-history.ts`: Crunchyroll history API served in the CR tab (`/auth/v1/token`, `/content/v2/{account}/watch-history`, `/content/v2/cms/seasons/{id}/episodes`, `cutNetworkAt` = Wi-Fi off at a precise request) and ADN `gw.api…/viewing/history` (CORS preflight answered; intercepted request headers include cookies, so `cookie` absence is a real check). Pages opened by the extension (`chrome.tabs.create`: import, Backup) are adopted with `h.waitForPage(prefix)`; `h.consoleMessages` collects every watched page's console. Downloads: `Browser.setDownloadBehavior` on `browser.target().createCDPSession()` (temp dir, `downloadWillBegin` gives the file name). Imported backup matches come back `unverified: true` (by design). Crunchyroll autoplay with the render 1.5 s behind the URL (`autoplayNextCrunchyroll` › `renderDelayMs`): the panel ends on the new episode's number (former `it.fails`, fixed 2026-10-14). Batch 4 (`lists.ext.ts`: links to the entry, remove from list, comments): 6 scenarios, ≈ 35 s; shared series, `launch`, `openPanel` and `openPopup` in `scenario.ts`. *On this page* in the popup: `openPopup(h, { behind: true })` opens it with `chrome.tabs.create({ active: false })` so the streaming tab stays active. Entry links: `target=_blank` click (also from a background tab) opens an unwatched tab whose target URL is asserted, then closed (its navigation dies on DNS; the panel follows it, so the streaming tab is brought back to front). `DEFER_RATING` is content-only (`sendFromContent`). Fakes: `removeEntry` simulates a removal on the site. Worker wake-ups (`worker-wake.ext.ts`, 1 scenario, ≈ 8 s): the worker is stopped with `ServiceWorker.stopAllWorkers` on a CDP session of the bridge page and observed through `ServiceWorker.workerVersionUpdated` (`runningStatus`; its target stays listed while the harness is attached); restarted under DevTools it waits for the debugger (Puppeteer's auto-attach), so `Runtime.runIfWaitingForDebugger` is sent to it on `starting`; a message must wake it (control), a page's `storage.session` and `storage.local` writes must not. Netflix (§4) is not automatable: `permissions.request` opens a native dialog that CDP cannot accept, even after a real click.
