# SyncKai 2.5.0 « Ta liste » — design

Status: approved by the owner on 2026-11-08 (« OK pour tout » on the builder-check questions and the §8 calls). Mockups: the « Maquettes SyncKai » and « Largeur du popup SyncKai » comparison pages (claude.ai artifacts, owner's choices of 2026-11-06 / 2026-11-08); the PNG sources live in the session scratchpad only, not in the repository.

## 1. Intent

2.5.0 makes the popup's « Mes séries » a better place to manage what you are watching, with four changes:

1. **A new popup shell**: a 56 px icon-only navigation rail on the left replaces the header and the top tabs, so the popup can grow new sections (2.6.0 adds « Pour toi ») without crowding a tab bar.
2. **Remaining time** on each series and a list total: « how long to catch up? ».
3. **Dormant series**: series left « Watching » for a long time are grouped apart, with Pause / Drop / Keep.
4. **AniList friends** on a series card: who among the people you follow has it, their status and score.

Why: the owner wants SyncKai to help with the list itself, not only sync it, while keeping the popup a quick tool (the side panel stays the place for long sessions).

## 2. Goals, non-goals, anti-goals

Goals
- Popup 496 × 600 px: rail 56 px + content column 440 px. Everything in the content column fits in German and Russian at 440 px.
- Every new number is honest: unknown data shows nothing, never a guess.
- No new permission, no new host, no Store « Privacy » change.

Non-goals (not in 2.5.0)
- « Pour toi » (recommendations), the Agenda in the popup, a « Stats » section: 2.6.0 or later. The rail is built so adding an entry is one item.
- A navigation rail in the side panel (too narrow: 320–400 px); the panel keeps its top tabs.
- An « Open in a tab » large dashboard (idea kept for later).
- Translating AniList tags (genres translation is a 2.6.0 topic).

Anti-goals (a failure even if it works)
- A popup that nags: no badge, notification or banner for dormant series.
- Hidden list changes: nothing is written to AniList / MAL without a click; every bulk write has a confirmation and an undo.
- Sending AniList or MAL more requests: remaining time and dormancy use the list already fetched; friends add at most one request per shown entry, batched and cached.

## 3. Constraints

- **AniList API terms** (`CLAUDE.md` › Authentication › AniList API terms of use): no hoarding (friends data cached 10 min, in memory / `storage.session`, never `storage.local`, never in backups); SyncKai complements AniList. The friends feature reads other users' public lists only through AniList's `isFollowing` filter for the signed-in user.
- **Design charter** (`docs/design/README.md`, tokens in `src/ui/theme.css`): dark theme only, one primary (sakura) action per surface, type scale tokens only (`design-tokens.test.ts` forbids new arbitrary sizes, so new sizes become tokens). The « Réessayer » button of a failed sync stays primary as the charter says (the mockups made it secondary; not adopted).
- **i18n**: every new string in English + context note (`docs/i18n/context.json`) + 20 translations following each term sheet, `npm run i18n:check`, `npm run test:i18n-layout` at the new popup width.
- **Tests first** where they pay off (pure rules: remaining time, formatting, dormancy, friends summary); UI checked afterwards by `test:e2e` and `test:i18n-layout`.
- **Architecture** (`src/architecture.test.ts`): shared components in `ui/components/`, pure rules in `shared/`, no new `addListener` in `background/`.

## 4. Approaches considered (owner's choices)

Popup width (page « Largeur du popup »): 440 px single column with top tabs (expert's first pick); 600 px rail; 600 / 800 px two panes; 800 px rail + master–detail; 680 px compact rail + two panes; **440 px content + left rail**, R64 (icon + label, 504 px) or **R56 (icons only, 496 px)**. The owner chose **R56, height 600**, wanting the rail's room for future sections without the two-pane cost (the popup hides 14 % of the video player instead of 32 % at 680 px), and prefers icons without labels. Consequence accepted: sections are not named in the rail, so each screen gets a title (§5.1).

Remaining time (page « Maquettes », 5 options): line 3 right of − / + (chosen) **plus** a « Temps restant » sort and a total line (option 5, also chosen). Rejected: suffix of the status line (truncated, hidden 3 s after each action), a numeric column (64 px off every title), menu / tooltip only.

Dormant series (4 options): **collapsed « En sommeil » group at the bottom of « Mes séries »** (chosen). Rejected: banner at the top, « À ranger » section in Activité, a Settings tool.

Friends (4 options): **collapsible « Amis sur AniList » section in the details (option 1) plus a summary line under « Ta liste » (option 2)**, both chosen. Rejected: a dedicated card, a header chip with a popover.

## 5. Design

### 5.1 Popup shell (rail R56)

Layout, 496 × 600 (`src/popup/popup.css`: `width: 496px; height: 600px`):

```
┌──────┬───────────────────────────────────────────┐
│ Kai  │ Screen title            (sort / actions)  │
│      │                                           │
│ [▶]  │ content column, 440 px                    │
│ [⏱]● │ (« Mes séries », « Activité », Settings)  │
│      │                                           │
│      │                                           │
│ ──── │                                           │
│ [▣]  ├───────────────────────────────────────────┤
│ [⚙]  │ status bar (48 px, under the content)     │
└──────┴───────────────────────────────────────────┘
```

- Rail (new shared component `ui/components/nav-rail.tsx`): full height, `surface` background, `line` border on the right. Top: Kai (28 px). Sections (2.5.0): « En cours » (`watching`) and « Activité » (`activity`, butter badge = items to handle, today's `pending`). Bottom, after a divider: open side panel (only when the browser has one and the active tab is known, as today) and Settings (pressed while Settings is open).
- Items 44 × 44 px, icon 20 px, `radius-panel`; selected = `raised` background + `field` border (neutral, never sakura); badge 16 px butter on the icon's corner, value in the accessible name (« Activité, 3 éléments à traiter », existing `nav.activityPending`).
- Semantics: `<nav aria-label={nav.sections}>` with a list of links / buttons, `aria-current="page"` on the current section (no `tablist`); Up / Down arrows move between items, Tab leaves the rail. Visible focus ring fits inside 56 px.
- Tooltip: custom, to the right of the item, shown on hover AND keyboard focus (never only `title`), `aria-hidden` (the name is on the item). Touch: no tooltip; the screen title names the section.
- Screen title: each content screen starts with a title row (`text-section` scale or the charter's screen title token, decided with the charter) naming the section (« En cours », « Activité », « Réglages » breadcrumb as today in Settings). It replaces the « SyncKai シンカイ » brand line, which disappears (Kai stays in the rail).
- Removed: `PopupHeader` and `PopupNav` (`src/popup/components/header.tsx`); `PopupTab` stays as the section id type. The status bar moves under the content column only.
- Settings opens in the content column (440 px instead of 400 px today).
- Model shared with the panel: the list of sections (id, icon, label, badge) can live in `ui/`, but the panel keeps its `Tabs`.
- Height 600 instead of 580: about 120 px more content than today (no header, no tabs row).

### 5.2 Remaining time

Data
- `WatchingEntry.episodeMinutes: number | null` (`shared/watching.types.ts`), from AniList `media.duration` (minutes; add the field to the `Watching` query in `background/anilist/watching.ts`) and MAL `average_episode_duration` (seconds → minutes, rounded; add it to the `fields` of the MAL watching request). A list cached before this version (no field) means unknown: no migration; the guard `isWatchingList` accepts the field as optional.
- Pure rules in `shared/` (new `shared/remaining-time.ts` or inside `shared/watching.ts`):
  - `episodesToCatchUp(entry, now)`: finished series = `total − progress`; airing series = released episodes − progress, where released = `nextEpisode.episode − 1`, or `nextEpisode.episode` when its `airingAt` is already past (same rule as the existing « Ép. N disponible » badge, reuse it); `null` when released episodes are unknown (airing without a next date, hiatus, not yet released) or `progress` is unknown.
  - `remainingMinutes(entry, now)` = `episodesToCatchUp × episodeMinutes`, `null` when either is unknown, `0`-or-less → `null` (nothing shown when up to date or ahead).
  - `formatRemaining(minutes, locale)`: under 60 min → minutes rounded to 5 (at least 5); 1 h to < 10 h → hours with one decimal rounded to half hours; ≥ 10 h → whole hours. Numbers through `Intl.NumberFormat(getLocale(), { maximumFractionDigits: 1 })`, units from the existing `time.countdown.*` keys, prefix « ≈ » from a translated key (ja 約…, zh 约 / 約, ko 약 …).
- Row (`ui/components/series-row.tsx`): line 3 wraps the stepper and the value: `⧗ ≈ 6,5 h` aligned right (`ml-auto`), `text-secondary`, `muted`, `tabular-nums`, new `hourglass` icon in `ui/icons.ts`. Safety net: the line has a fixed height and `overflow-y-clip` with `flex-wrap`, so a value that does not fit drops to an invisible second line and disappears whole, never cutting the stepper. Screen reader text: « Environ 6,5 heures pour finir » (long units, `Intl.NumberFormat` `unitDisplay: 'long'`); tooltip with the detail « 16 épisodes × 24 min » / « 2 épisodes sortis à voir × 24 min ». Same value on the « Reprendre » card if it fits (builder's call).
- Total line under the « Mes séries » heading: « ≈ 24 h à rattraper · 5 séries », sum over the series that have a value (dormant ones included), hidden when 0 or none.
- Sort: a new `WatchingSort` value `'time'` (« Temps restant », shortest first, unknown last, then by title), and the existing `'remaining'` (« Épisodes restants ») aligned on `episodesToCatchUp` instead of `total − progress`, so both count released episodes only. Settings normalization accepts the new value; an unknown stored sort falls back as today.

### 5.3 Dormant series (« En sommeil »)

Rule (pure, `shared/`): an entry is dormant when all hold:
- its list status is `CURRENT` (never `REPEATING`, never other statuses);
- the dormancy setting is not `never`;
- last activity = the latest of the list entry's `updatedAt` and SyncKai's `lastSync.at` is known and older than the threshold;
- it is not waiting for its next episode: when `episodesToCatchUp` is known, it must be > 0 (a series up to date on an airing schedule is never dormant); when it is unknown (hiatus, airing without a next date, finished with an unknown total, MAL entry without AniList data), the series is eligible on inactivity alone (owner's decision of 2026-11-08: nothing moves without a click, so a false positive costs nothing);
- it is not marked « Garder » (see below) for the current threshold window.

Display (`popup/components/watching-screen.tsx`)
- Dormant entries leave the sorted list and go into a group at its end: header button (Kai asleep, « En sommeil », count chip, subtitle « Rien vu depuis plus de 30 jours »), collapsed by default, open state remembered in the popup preferences. Inside, longest-inactive first, whatever the sort. No group when none. The « Reprendre » series never appears twice.
- Each row: the usual row (cover, title, line 2 « Ép. 7 / 23 · vu il y a 2 mois » with `Intl.RelativeTimeFormat`: weeks under 60 days, months after), and three actions: « Pause » (secondary, no confirmation, result banner with « Annuler »), « Abandonner » (secondary, inline confirmation like the « ⋯ » menu's), « Garder » (text button).
- « Tout mettre en pause » (only with 2+ entries): inline confirmation « Mettre 4 séries en pause ? Sur AniList et MyAnimeList. Tu pourras annuler juste après. », then the existing watching notice banner with « Annuler » (restores `CURRENT` while shown). No bulk drop.
- Footer link « Seuil : 30 jours » opens Settings › Display at the setting.
- Writes go through the existing status actions (`runOnServices` with the sessions read before the request), one entry at a time; partial failure shows the existing warning banner with « Réessayer ».
- Per service (assistant's call, builder check of 2026-11-08): Pause and Drop write only to a service whose entry is `CURRENT` at write time (fresh read inside `runGuarded`); a service where the entry is missing, already paused / dropped / completed or rewatching is skipped and reported as unchanged, never overwritten. This needs a dormant-specific decision rule next to `decideStatusChange` (`background/sync/rules.ts`), which today writes whatever the current status is.
- Undo restores, on each service actually written, the status read before the write (always `CURRENT` given the rule above): `ListStatusChange` gains `'CURRENT'`, and the screen keeps the per-service « before » until the banner closes. The banner's « Annuler » is new code (the existing notice banner only offers « Réessayer »). After an undo the series comes back to the active list for a full threshold (its `updatedAt` changes): intended.

Storage
- Setting `dormantAfterDays: 30 | 60 | 90 | null` (`shared/settings.ts`, default 30, normalized, in backups), shown in Settings › Display (« Séries en sommeil », segmented 30 / 60 / 90 jours / Jamais).
- « Garder » marks: a new key in `protocol/storage-keys.ts` (e.g. `watching:keptDormant`) `{ [entryKey]: { keptAt, epoch } }`, account-bound (epoch, purged at sign-out with the other account data), at most 200 entries, written under the storage lock; a mark stops counting when newer activity exists or after one threshold.

### 5.4 AniList friends

Data
- AniList only (hidden for MAL-only users and without an AniList session). Query (authenticated): `Page(perPage: 50) { pageInfo { total } mediaList(mediaId: $id, isFollowing: true, sort: [STATUS, SCORE_DESC]) { status progress score(format: POINT_10_DECIMAL) user { id name avatar { medium } } } }`. Request budget (owner's decision of 2026-11-08): friends are fetched only for the entry the card or the panel shows, once it has stayed the same for 1.5 s (a quick succession of season picks or navigations sends nothing), one request per entry, interactive lane, never folded into `PageMediaBatch` and never prefetched for the picker seasons. The frozen counts of `page-media/series-requests.test.ts` stay as they are for picks made within 1.5 s of each other; a settled entry adds one request, cached 10 min.
- Reduced to `{ total, averageScore, scoredCount, friends: [{ id, name, avatar, status, progress, score }] }` by a pure reducer (`shared/`), with a guard. Average over scores > 0; fewer than 2 scores → no average.
- Cache 10 min keyed by `accountFingerprint` + media id (as `trackers/entry-cache.ts`), in memory / `storage.session`; never `storage.local`, backups or the diagnostics report. A sign-out drops it.

Display
- Summary line in « Ta liste » (popup « Sur cette page » card; panel `list-card.tsx`): avatars stack (3) + « 7 amis · ★ 8,6 », a button that opens the friends section (and scrolls it into view). Hidden when no friend has the series.
- Section « Amis sur AniList » (panel `details-card.tsx` as a `Collapsible` section `friends`, after « Note et commentaire »; popup: last part of the card's details): comparison band (friends' average vs your score), up to 5 friends (avatar, name linking to the AniList profile in a new tab, status dot + third-person status label, « Ép. x / y », score or « — »), « Voir les N autres » (in place), « Tout voir sur AniList ↗ », and the privacy line « Listes publiques des personnes que tu suis. Rien n'est gardé. ».
- States: loading skeleton (`aria-busy`), error « Indisponible » + « Réessayer » in the section, hidden when none / no account / expired session (the usual « Session expirée » path).
- New i18n keys for third-person statuses (`friends.status.*`), distinct from `page.status.*` (German « Schaut gerade » vs « Schaue ich »).
- Avatars through `toImageSrc` (`s4.anilist.co` already in `IMAGE_HOSTS`).

### 5.5 Release status in « Mes séries » (added 2026-11-09)

Owner's choice on the mockups page: option 2 (status chip for the exceptional states) plus option 4 (a « État » sort with groups). Why: today a cancelled series shows « Série terminée » and a series on hiatus or not yet released without a date shows « Date inconnue », so the line-2 badge mixes four states.

Chip (option 2)
- Pure rule in `shared/` (next to `nextEpisodeBadge`): `releaseChip(entry): 'RELEASING' | 'NOT_YET_RELEASED' | 'HIATUS' | 'CANCELLED' | null` from `WatchingEntry.airingStatus`; `FINISHED` and `null` give no chip.
- Shown on line 2, after the next-episode badge, in the place and size of the existing « Exclue » tag (`SeriesTag`, generalized with a tone and an icon). « Exclue » keeps priority when both do not fit: the status chip truncates with its full text in a tooltip.
- Tones and icons (owner's decision of 2026-11-09, replacing the assistant's first proposal): RELEASING green (mint), play icon; FINISHED no chip, the existing « Série terminée » badge stays; NOT_YET_RELEASED grey (muted), `calendar`; HIATUS yellow (butter), `pause`; CANCELLED red (danger), `ban`; unknown status: nothing. Never sakura. Texts: the existing `page.airing.*` keys (already in 21 languages). The icon is `aria-hidden`; the text is read. Note: in the charter butter also marks « to handle » and danger « failure »; the owner chose them knowingly for hiatus and cancelled.
- A cancelled series no longer shows « Série terminée »; for NOT_YET_RELEASED, HIATUS and CANCELLED the chip replaces the « Date inconnue » / « Série terminée » badges; the other badges (« Ép. N disponible », « Ép. N dans … », « Prochain épisode bientôt ») stay.
- During the 3 s action feedback that replaces line 2 (« Ép. 5 vu »), the chip is hidden with the rest of the line (assistant's call: same behaviour as the badge today).

« État » sort (option 4)
- New `WatchingSort` value `'status'`: groups in this order, each with a header « LABEL · count »: airing (RELEASING), upcoming (NOT_YET_RELEASED), finished (FINISHED), stopped (HIATUS + CANCELLED), unknown status last; inside a group, the « next episode » order. Empty groups are not shown.
- Dormant series stay in the « En sommeil » group at the end, whatever the sort (§5.3); the « Reprendre » series is never shown twice.
- New keys: the sort label and its aria label (`watching.sort.status`, `watching.sortAria.status`) and four group titles (`watching.statusGroup.{airing,upcoming,finished,stopped}`), each with its note and 20 translations.
