# Store images

Generated by `npm run screenshots` (`scripts/screenshots/`): the **real** popup, side panel and in-page bubble (`src/`) are rendered by Puppeteer with a mocked `chrome` API (`mock-chrome.ts`: storage, `storage.session`, `tabs.connect` ports, `sidePanel`) and fictional demo data (`demo-data.ts`, `demo-panel.ts`: no real account or token) on real AniList entries (`demo-media.ts`), shown with their real AniList covers (see Covers below). Every PNG is RGB 24-bit, no alpha, checked by `capture.ts`.

```bash
npm run screenshots                         # 5 shots × fr/en/de + marquee tile (removes stale shots)
npm run screenshots -- --locale de --shot 4 # a single shot
npm run screenshots -- --shot marquee       # the marquee tile only
npm run screenshots -- --covers placeholder # placeholder covers instead of the real AniList ones
```

- The popup footer shows the version read from `manifest.json`: regenerate after a version bump.
- No invented entry or date on a real series in the store images (owner's decision of 2026-11-12): the watch order (shot 2, marquee) shows the real Mushoku Tensei franchise (`demo=mushoku` in `demo-panel.ts`) and Announced (shot 4) real coming sequels (`announcedDemo` in `demo-data.ts`), with the titles, formats, statuses and dates AniList gave on 2026-11-12, hardcoded. Only the list states are the fictional account's. When AniList changes these entries (a date announced, a season out), check them again against the API and update the values. The panel heights (shot 2: 696 px, shot 4: 632 px) put the footer between two rows: check that no row is cut after a change.
- The For you shot (3) fixes `Math.random` in `popup-frame.ts` so the same suggestion is always drawn (Jujutsu Kaisen, « Because you rated Dandadan ★ 9/10 »); the suggestions carry their real AniList format, year, episodes, score, genres and a real streaming platform. The Stats shot (5) uses fictional profile statistics and 30 days of activity (`demo-data.ts`, scenario `stats`), with the « Watching » series caught up so that the activity, the totals and the statuses fit without scrolling.
- Captions: `scripts/screenshots/captions.ts` (`*word*` = lavender highlight, `\n` = forced line break: 52 px titles in a 430 px column, 3 lines at most, an overflowing line is logged as an error), one katakana word per shot (`KANA`). Layout: `banner.ts` / `banner.css`.
- Visual identity, direction C « Duo / editorial » (charter tokens): a vertical spine with the shot's kana as a faint watermark cut by the left edge, then a text column (lockup, eyebrow + the same kana in sakura, the only sakura accent, title with one word in lavender, rule, subtitle, row of logos: five platforms → AniList / MAL), and on the right a lighter surface with a large disc and the real UI as a floating card (bubble ×1.6 over the player, side panel ×1 in front of the player, Announced ×1.25, popup ×1.2).
- Frames: `popup.html` (popup, `?scenario=watching|page|activity|foryou|stats|…`, sections opened through the real rail buttons), `sidepanel.html` (`?tab=nowPlaying|agenda`, `&demo=mushoku` plays Mushoku Tensei Season 3 instead of the end-to-end Frieren demo, `&reveal=order` opens the whole watch order (« All » view, every entry) at the top of the panel, `&view=announced` switches the Schedule to Announced through the real segmented control), `import-cr.html` (import preview, no longer in the store set), `player.html` (`?kind=sync|rate|watch`, `&label=` episode title of the `watch` scene, `&layer=scene|toast`: player alone, or the bubble alone on a transparent page so it can overflow the player card).
- Covers (owner's decision of 2026-10-18, reversing the placeholders chosen on 2026-10-16; IP risk accepted, as other trackers such as MAL-Sync show real covers): by default the shots and the marquee tile show the **real AniList covers** of the demo entries and the real banner of the side panel hero. `anilist-covers.ts` reads them at generation time with ONE anonymous batched query to `https://graphql.anilist.co` (`Page(perPage: 50) { media(id_in: [...]) }`: `coverImage.extraLarge`, else `large`, plus `bannerImage` and `coverImage.color`), keeps the answer for a week in `<os.tmpdir()>/synckai-screenshot-covers.json` (no request on the next runs), and the harness injects the URLs (s4.anilist.co, an `IMAGE_HOSTS` host) into the pages (`__SYNCKAI_DEMO_COVERS__`, read by `covers.ts`). No image file is stored in the repository: the covers only end up inside the generated PNGs. `markReady` waits for every image in view to load (a remote image still missing after 20 s is logged as an error). Every demo id must be the series it is shown as: `demo-media.ts` lists them with their AniList titles (checked against the API on 2026-10-18), and `coverUrl` only takes one of its ids (`DemoMediaId`).
- Fallback: `--covers placeholder` or `SYNCKAI_SCREENSHOT_COVERS=placeholder` renders the abstract duotone placeholders of `covers.ts` without any network request (e.g. if a store review objects to the cover art). If AniList is unreachable, the run warns and falls back to the placeholders; an entry without an AniList image keeps its own placeholder. The end-to-end tests and the component gallery always use the placeholders.
- Kana (shared by the three languages, checked against the ja catalog and `docs/i18n/glossary/ja.md`): 1 キロク (記録, saved: `toast.title.saved`), 2 ジュンバン (順番, order: `panel.order.title` 視聴順), 3 オススメ (おすすめ, recommended: `reco.title`, glossary « Recommended »), 4 ハッピョウ (発表, announced: `agenda.view.announced` 発表済み), 5 トウケイ (統計, stats: `nav.stats`); promo tiles ジドウ (自動, automatic).
