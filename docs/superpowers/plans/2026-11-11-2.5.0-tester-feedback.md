# 2.5.0 tester feedback: implementation plan

The owner's manual tests of `698849f` (2026-11-11) found one regression and asked for two changes before the 2.5.0 tag: « à faire ici ». POP-01 (`docs/audit/2026-11-10/findings.md` › 4) is now confirmed: at Chrome page zoom 110 %, the popup's status bar is cut off at the bottom.

## Owner decisions (2026-11-11)
- **POP-01:** the popup keeps its layout at every zoom level. The status bar stays visible, and the list scrolls in the height Chrome allows. The text size follows the user's zoom; never scale it back (WCAG 1.4.4).
- **« Actualiser »:** a refresh button in « Mes séries », for changes made on AniList or MAL outside SyncKai.
- **Announced sequels:** the « Annoncées » view must not offer « + À regarder » for a series that is already in one of the user's lists, even when it was added outside SyncKai after the last daily pass.

## Global Constraints
These are the same as `docs/superpowers/plans/2026-11-11-2.5.0-audit-fixes.md` › Global Constraints, which apply verbatim:
- tests first;
- the UI-string rules (en, context note, 20 translations, review logs, `i18n:check`, `test:i18n-layout`);
- checks through `synckai-verify`;
- the Git rules (the controller creates the branch; commit on it only; no push, merge, stash or tag; no mention of Claude);

On top of those:
- **AniList terms** (`docs/memory/auth-and-api-terms.md`): fetch what is shown, cache briefly, no bulk crawl.
- **MAL rule:** reading the user's own MAL list is allowed, as in the daily sequel pass. No other MAL call.
- **Service worker** (`docs/memory/architecture.md`): no new `addListener` in `src/background/`, and new messages go into the typed protocol of `src/protocol/messages.ts`.
- **Account-bound writes:** respect the session epochs.

## Task 1: The popup fits the height Chrome gives it at any zoom (POP-01)
**Branch:** `bugfix/popup-zoom`
- Today, `src/popup/popup.css:5-10` sets `html, body { width: 496px; height: 600px; overflow: hidden }`. Chrome caps a popup at 600 DIP, so at 110 % about 55 CSS px are cut and nothing can scroll.
- The layout must fit the window's real height:
  - the status bar is always fully visible at the bottom;
  - the main area scrolls;
  - there is no horizontal scrollbar;
  - at 100 %, it looks exactly as today: no scrollbar, same size.
- Constraint: auto-sized popups collapse with `vh` units. Keep the fixed 600 px as the requested size, and adapt to `window.innerHeight` when the window is smaller: for example a `max-height`, or a height set through the CSSOM after the first layout and on `resize`. Choose the smallest robust option and justify it in the report.
- **Test first:** an e2e that opens `popup.html` in a 496 × 545 viewport, the size of a 600 px popup at 110 %. It asserts that the status bar is entirely inside the viewport (today it is not), and that the « Mes séries » list can scroll to its last row. At 496 × 600 nothing changes. Run `test:i18n-layout`.

## Task 2: « Actualiser » in « Mes séries »
**Branch:** `feature/watching-refresh`
- Add a small refresh button in the « Mes séries » header, next to the sort control. It is an icon button with a tooltip and an accessible name; reuse the existing icon set.
- It forces a fresh read of the shown list, bypassing the service worker's watching cache (about 90 s; `src/background/anilist/watching.ts`), for the connected services.
- While the read runs, the button is busy (spinner) and inactive. On failure, the existing visible error path shows (expired session, rate limit, network).
- At most one read in flight. No periodic or automatic refresh.
- **New UI string:** e.g. `watching.refresh` « Actualiser la liste », in 21 languages, with a context note. Follow the UI-string rules.
- **Test first:**
  - the controller: a click sends the watching request with the fresh flag, and a second click while busy sends nothing;
  - the worker: the fresh flag skips the cache;
  - the e2e: the button exists and triggers the read.

## Task 3: « Annoncées » checks the shown sequels against the user's lists
**Branch:** `bugfix/announced-in-list`
- Today `visibleSequels` (`src/shared/sequels.ts`) shows every record that is not dismissed. Records are pruned only by the daily pass, so a sequel added to a list on AniList after the pass keeps « + À regarder » for up to 24 h.
- When the « Annoncées » view opens in the side panel, or the popup's Activité sequel section shows, the worker checks the shown record ids against the user's lists:
  - **AniList connected:** one request for the shown ids (`Page(perPage: 50) { media(id_in: …) { id mediaListEntry { status } } }`, with the token; chunked by 50 if there are more), on the background or interactive lane as the code's conventions say;
  - **MAL-only:** the user's own MAL list, through the existing memo of `src/background/franchise/states.ts` if it fits, matched by `idMal`.
- A record found in any list is removed from the store through the existing path that the « already in list » outcome uses (it ends the alert and is never renotified). The rows disappear.
- **Throttle:** at most one check per 10 minutes per account, so that switching views does not repeat it. The result is account-bound (session epochs). A failed check changes nothing and shows nothing; the rows stay as they are.
- Use one shared worker message for both the side panel and the popup.
- **Test first:**
  - worker: records 1 and 2 shown, AniList says 2 is CURRENT → 2 removed from the store, 1 kept;
  - throttle: a second call within 10 min makes no request;
  - session change during the check → nothing written;
  - MAL-only path;
  - panel: opening « Annoncées » sends the check once.
