# Store images

Generated by `npm run screenshots` (`scripts/screenshots/`): the **real** popup, side panel, Crunchyroll import page and in-page bubble (`src/`) are rendered by Puppeteer with a mocked `chrome` API (`mock-chrome.ts`: storage, `storage.session`, `tabs.connect` ports, `sidePanel`) and fictional demo data (`demo-data.ts`, `demo-panel.ts`: no real account or token) on real AniList entries (`demo-media.ts`), shown with their real AniList covers (see Covers below). Every PNG is RGB 24-bit, no alpha, checked by `capture.ts`.

```bash
npm run screenshots                         # 5 shots × fr/en/de + marquee tile (removes stale shots)
npm run screenshots -- --locale de --shot 4 # a single shot
npm run screenshots -- --shot marquee       # the marquee tile only
npm run screenshots -- --covers placeholder # placeholder covers instead of the real AniList ones
```

- The popup footer shows the version read from `manifest.json`: regenerate after a version bump.
- The Schedule shot (3) shifts the panel's clock to Tuesday 2 pm of the current week (`sidepanel-frame.ts`): Monday's episode ticked, two releases today, Wednesday next, no row cut by the footer. The dates shown follow the generation week, which is expected.
- Captions: `scripts/screenshots/captions.ts` (`*word*` = lavender highlight, `\n` = forced line break: 52 px titles in a 430 px column, 3 lines at most, an overflowing line is logged as an error), one katakana word per shot (`KANA`). Layout: `banner.ts` / `banner.css`.
- Visual identity, direction C « Duo / editorial » (charter tokens): a vertical spine with the shot's kana as a faint watermark cut by the left edge, then a text column (lockup, eyebrow + the same kana in sakura, the only sakura accent, title with one word in lavender, rule, subtitle, row of logos: five platforms → AniList / MAL), and on the right a lighter surface with a large disc and the real UI as a floating card (bubble ×1.6 over the player, Schedule ×1.25, popup ×1.2).
- Frames: `popup.html` (popup), `sidepanel.html` (`?tab=nowPlaying|agenda`, `&reveal=relations` scrolls to the first sequel), `import-cr.html` (import preview), `player.html` (`?kind=sync|rate|watch`, `&layer=scene|toast`: player alone, or the bubble alone on a transparent page so it can overflow the player card).
- Covers (owner's decision of 2026-10-18, reversing the placeholders chosen on 2026-10-16; IP risk accepted, as other trackers such as MAL-Sync show real covers): by default the shots and the marquee tile show the **real AniList covers** of the demo entries and the real banner of the side panel hero. `anilist-covers.ts` reads them at generation time with ONE anonymous batched query to `https://graphql.anilist.co` (`Page(perPage: 50) { media(id_in: [...]) }`: `coverImage.extraLarge`, else `large`, plus `bannerImage` and `coverImage.color`), keeps the answer for a week in `<os.tmpdir()>/synckai-screenshot-covers.json` (no request on the next runs), and the harness injects the URLs (s4.anilist.co, an `IMAGE_HOSTS` host) into the pages (`__SYNCKAI_DEMO_COVERS__`, read by `covers.ts`). No image file is stored in the repository: the covers only end up inside the generated PNGs. `markReady` waits for every image in view to load (a remote image still missing after 20 s is logged as an error). Every demo id must be the series it is shown as: `demo-media.ts` lists them with their AniList titles (checked against the API on 2026-10-18), and `coverUrl` only takes one of its ids (`DemoMediaId`).
- Fallback: `--covers placeholder` or `SYNCKAI_SCREENSHOT_COVERS=placeholder` renders the abstract duotone placeholders of `covers.ts` without any network request (e.g. if a store review objects to the cover art). If AniList is unreachable, the run warns and falls back to the placeholders; an entry without an AniList image keeps its own placeholder. The end-to-end tests and the component gallery always use the placeholders.
- Kana (shared by the three languages, checked against the ja catalog and `docs/i18n/glossary/ja.md`): 1 キロク (記録, saved), 2 サイセイ (再生, now playing), 3 コンシュウ (今週, this week), 4 ページ (page, former kana of « On this page »), 5 リレキ (履歴, history); promo tiles ジドウ (自動, automatic).
