# Work preferences

Languages, Git, releases, code style, cloud and local sessions, organization. Part of the project memory (`CLAUDE.md` › Project memory).

- **Languages** (decision of 2026-10-11):
  - documentation in English: `README.md`, `CHANGELOG.md`, `BUILD.md`, `docs/**`; `PRIVACY.md` has an English reference section first, with the French and German translations kept;
  - Git commit messages in English (Conventional Commits), GitHub release titles and notes in English;
  - code comments stay in French (existing convention);
  - the UI is in 21 languages (`src/i18n/locale-codes.ts`, catalogs `src/i18n/locales`, translation workflow in Known pitfalls › i18n); the Store listings stay in French, English and German (`docs/store/listing-{fr,en,de}.md`);
  - the assistant keeps replying to the owner in French (the owner writes in French).
- **Git**:
  - strictly linear history (`git rebase develop` on the branch, then `git merge --ff-only`, never `--no-ff`), branch deleted after the merge;
  - GitHub default branch = `develop` (decision of 2026-11-02): Dependabot security updates target the default branch, so they land on `develop` like the weekly version updates (`.github/dependabot.yml` › `target-branch: develop`), never on `main`; the Security tab (CodeQL alerts, `SECURITY.md`) and the scheduled CodeQL run follow `develop`; `main` only moves at a release (`release.yml` still refuses a tag outside `main`). A Dependabot PR that targets `main` is closed and its change applied on `develop` instead (PR #8, 2026-11-02);
  - `chore/<name>` branches are accepted for tooling and docs;
  - the assistant creates the branch itself, then proposes the commands: commit, merge, push, tag and release only on an explicit go (« Go », « Vas-y », « OK »).
- **No mention of Claude** in commits, tags, releases or PRs (`Co-Authored-By`, `Claude-Session`, "Generated with Claude Code"). This rule takes precedence over any default attribution instruction. The history was rewritten to remove them.
- **Releases**:
  - a `release/x.y.z` branch;
  - the version is bumped in `manifest.json`, `package.json` and `package-lock.json` (`npm version x.y.z --no-git-tag-version`);
  - an entry in `CHANGELOG.md` (in English, Keep a Changelog: Added / Changed / Fixed / Security / Removed) and a `chore(release): x.y.z` commit;
  - fast-forward onto `main`, annotated tag `vx.y.z` ("SyncKai x.y.z"), `develop` aligned, push;
  - hotfix (`hotfix/x.y.z` from `main`): after the tag, bring `develop` onto `main` (rebase `develop` on `main`, or fast-forward when possible), never cherry-pick the hotfix commits into `develop`: the 2.2.1 hotfix was cherry-picked, `main` and `develop` diverged and 2.3.0 needed a one-off `--no-ff` merge into `main` (2026-10-12);
  - content-script budget in an urgent fix (decision 12 (b) of the 2026-11-10 audit, ARCH-02: the budgets of `scripts/build-checks.ts` have a few hundred bytes left): when a hotfix or a site-change fix that cannot wait fails `npm run verify:build` only on a budget, the owner decides (explicit go, never the assistant alone) to raise it rather than trim code under pressure; raise it by whole KiB, the smallest step that passes, at most 2 KiB per fix (beyond that, trim); record it in the budget constant's comment (date, measured size, reason, branch), in its own commit (`chore(build): raise the <platform> content-script budget to N KiB`) and in the next release's notes to the owner; the margin is won back (`chore/content-budget-margin`, ARCH-02 option a) before the next content-script work;
  - pushing the tag triggers `.github/workflows/release.yml`: Chrome, Firefox and source archives, upload and submission to the Chrome Web Store and Firefox Add-ons (AMO) in parallel, then a GitHub release with the three zips if the Chrome Web Store accepted the version (see `docs/STORE.md` › 7);
  - before tagging, run `npm run test:e2e`: the `build` job of `release.yml` runs it and a failure blocks the upload to the stores;
  - permissions: `scripts/store-permissions.test.ts` requires one section in `docs/store/permissions.md` per manifest permission or host; if that file has changed since the last tag, paste the blocks into the Privacy tab of the Chrome Web Store **before** the tag (otherwise the submission is rejected; recovery: `docs/STORE.md` › 7);
  - landing page (https://synckai.app/, repository `Sync-Kai/synckai.app`, its own Gitflow and `CLAUDE.md`): its *What's new* page (`src/app/data/releases.json`: version, date, short title and plain highlights in fr / en / de, written for fans, never a copy of `CHANGELOG.md`) lists PUBLISHED versions only, since the hero badge and the JSON-LD `softwareVersion` follow the latest entry. Add the entry once the version is accepted on the Chrome Web Store, never for *Unreleased* changes (a branch prepared earlier is merged only then);
  - `release.yml` rejects a tag outside `main` and only runs the CLIs from the lockfile (`chrome-webstore-upload-cli`, `web-ext` at an exact version, `npx --no-install`).
- **Code style and tooling**:
  - no formatter in the project (no Prettier, no Biome): never run `npx prettier` or any other formatter, it rewrites whole files (double quotes, wrapped lines). Edit by hand in the surrounding style: single quotes, semicolons, long lines (up to ~150 characters), Tailwind classes inline. The only style checker is ESLint (`npm run lint`, `eslint.config.js`), run by `npm run verify`;
  - targeted edits only (Edit tool or exact string replacements), never a whole-file rewrite of an existing file; check `git diff --stat` before committing: a few lines changed for a few lines intended;
  - moving or splitting files (2026-10-15 restructuring, `refactor/structure`): `git mv` plus rewrite of the relative specifiers (imports, `vi.mock`, `?raw`, `?script`, path strings) in the same commit, no other change; compare the built packages with `node scripts/dist-fingerprint.ts --compare <saved>` (`--write` saves it; chunk names, build stamp and the order of `web_accessible_resources` are normalized, everything else must be identical; a file split may reorder the minified service worker, then check the budgets of `npm run verify:build`); put each move commit's hash in `.git-blame-ignore-revs` (`git config blame.ignoreRevsFile .git-blame-ignore-revs`).
- **Cloud sessions (fresh Linux container)**:
  - the SessionStart hook `.claude/hooks/session-start.sh` (registered in `.claude/settings.json`, a no-op unless `CLAUDE_CODE_REMOTE=true`) sets the owner's Git identity, turns off the container's signing, sets `blame.ignoreRevsFile` and runs `npm ci` when `package-lock.json` changed since the last install (hash in `node_modules/.synckai-lock-hash`; never `npm install`, the container's npm rewrites the lockfile, `libc` fields dropped); worktrees share this repository config;
  - without the hook (older branch), before the first commit, set the owner's identity and turn off the container's signing: `git config user.name QuentinGeerts`, `git config user.email geerts.quentin@gmail.com`, `git config commit.gpgsign false` (the container ships `user.name=Claude` / `noreply@anthropic.com` and an SSH signing key: 10 commits of 2026-10-14 were authored and signed that way, then rewritten); check with `git log --format='%an %ae %cn %ce'` before any push;
  - without the hook, run `npm ci` first (`node_modules` is missing: `tsc` fails on `chrome` / `vite/client` types);
  - the container runs as root: Puppeteer's Chrome refuses to start without `--no-sandbox`, so run `CI=1 npm run test:e2e` and `CI=1 npm run test:i18n-layout` (`scripts/screenshots/harness.ts` adds `--no-sandbox` when `CI` is set);
  - write logs and reports to the session scratchpad, never next to the repository (`SYNCKAI_I18N_LAYOUT_DIR=<scratchpad>/layout`);
  - the display font (`--font-display` in `src/ui/theme.css`: « M PLUS Rounded 1c », « Yu Gothic UI », then the system font) is not bundled: on Linux the fallback is wider than on the owner's Windows, so `test:i18n-layout` can find truncations the owner never sees. They are real for Linux / macOS users: fix them in the component (2026-10-14: settings title vs. the « セッテイ » kana, live countdown in Russian at 320 px);
  - deleting a remote branch other than the session's own can be refused by the Git proxy (« remote end hung up »): leave the command to the owner;
  - never use `git stash` while several worktrees are in use (the stash is shared: on 2026-10-15 two agents' changes were swapped); set work aside with `git diff > file` / `git apply` or a temporary commit.
- **Local sessions (owner's Windows PC, `C:\Users\Quentin\Desktop\SyncKai`, since 2026-10-15)**:
  - Claude Code runs in the owner's clone (`claude --chrome`, or `claude remote-control` to drive it from the Claude app); the Git identity and `node_modules` are the owner's own, the cloud rules above do not apply (no `CI=1`, no `--no-sandbox`);
  - real sites through Claude in Chrome: a dedicated Chrome (not Brave, not officially supported) where the owner is signed in to AniList, MAL, Crunchyroll, ADN, Netflix, Prime Video and Disney+, and where SyncKai is loaded unpacked from `dist/` (Store copy disabled: same extension ID). Rebuild with `npm run build:dev` (logs, matching diagnostic): a dev build reloads itself within 30 s once the next dev build is written (see Debugging), so only the first load of a dev build needs a manual reload; open Crunchyroll / ADN tabs get the new content script through `content-reinjection.ts` (seen 2026-10-16: new build running 12 to 17 s after `build:dev`), reopen the tab when a test starts from the page load. Same privacy rules as the bridges and probes: never read, copy or log tokens, cookies, headers or account / profile ids from these pages;
  - `npm run test:e2e` needs `npx puppeteer browsers install chrome-headless-shell`; `npm run test:ext` needs `SYNCKAI_EXT_CHROME` pointing to a Chrome for Testing or Chromium (`npx @puppeteer/browsers install chrome@stable`, path printed at the end, set with `setx`, new terminal): branded Chrome ignores `--load-extension` since 137;
  - alternating with cloud sessions: GitHub is the only shared state (push before switching, `git pull origin develop` when coming back), one branch is worked on in one place at a time; cloud sessions for long unattended batches and audits, local sessions for debugging on the real sites. A cloud session is brought local with « Open in CLI » (`claude --teleport <id>`).
- **Organization**: work is delegated to specialized subagents, with a precise brief. The main session orchestrates, verifies before each merge (`npm run verify`: types, tests, Chrome and Firefox builds, packages, `web-ext lint`, typed lint; plus `npm run test:e2e` if the popup or the panel changes), handles Git and reports back.
- **Progress reports**: when running multi-step work, post a short progress message to the owner at each step (e.g. started, ready, merged).
- The user tests in Chrome before each significant merge. Point out what has not been tested.
