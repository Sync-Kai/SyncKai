# i18n

21 locales: translation workflow, layout check, composed texts, lazy catalogs, plurals, locale matching. Part of the project memory (`CLAUDE.md` › Project memory).

- **i18n** (21 locales: infrastructure of 2026-10-13, the 18 new catalogs translated then independently reviewed on 2026-10-13/14):
  - translation workflow: shared rules in `docs/i18n/GLOSSARY.md`; one translator note per en key in `docs/i18n/context.json` (where, meaning, placeholders, length; enforced by `scripts/i18n-context.test.ts`); per-locale term sheet `docs/i18n/glossary/<code>.md` (binding for every later change) and review log `docs/i18n/review/<code>.md` (later changes logged there too); `npm run i18n:check [-- <codes>]` (0 errors). Adding or changing a UI string = its en text, its context note and its 20 translations in the same change (each language's term sheet), then the layout check. Removing the last use of a key removes the key from the 21 catalogs and `context.json` in the same change: `src/i18n/unused-keys.test.ts` fails on any en key that the production code of `src/` (tests excluded) never cites, as a literal or under a built prefix (`` `page.status.${…}` ``, `'genre.' + …`: a prefix counts only when it ends with a dot); seven dead keys were removed this way on 2026-11-13 (audit ARCH-05);
  - layout check: `npm run test:i18n-layout` (≈ 40 s; the real popup, side panel at 360 / 320 px, import page and Backup page in every locale; report and annotated screenshots in `os.tmpdir()/synckai-i18n-layout` or `SYNCKAI_I18N_LAYOUT_DIR`, never in the repo; `SYNCKAI_I18N_LAYOUT_LOCALES=de,ja` for a few locales). Excluded from `npm run test:e2e` on purpose: a long translation never blocks a release. In CI, informative job `i18n-layout` of `ci.yml` (`continue-on-error`: always green; a `::warning` with the findings count, the report in the run summary, report and annotated screenshots in the `i18n-layout` artifact, 14 days). A finding is fixed in the component first (wrap, truncate with a tooltip, container query), then by shortening that translation (term sheet respected, change logged in its review log); only an intentional case goes into `scripts/e2e/i18n-layout.allowlist.json`, with its reason;
  - composed texts (helpers of `i18n/core.ts`, content-safe): two translated sentences are never joined with a plain space (`joinSentences`: no space in ja / zh-CN / zh-TW, the language's full stop added to a sentence without one); a suffix that starts with its own punctuation goes through `appendSuffix` (never « .. » / « 。。 »); lists of names through `formatList` (Intl.ListFormat: 、 in ja / zh, and in zh a space between 和 / 或 and a Latin name), never `.join(', ')`; quantities with units through `joinQuantities` (no space in ja: « 1時間30分 »). A value whose position depends on the language is a placeholder, never appended by the code (`{year}` of `panel.nowPlaying.season.*`: « 2024年秋 »); numbers in a text go through `Intl.NumberFormat(getLocale())` (`agenda.adjust.help`); signed delays (`formatOffset`) use the `time.countdown.*` units;
  - list: `src/i18n/locale-codes.ts`, leaf module without imports (BCP 47 codes = value stored in the `language` setting = catalog name; `LanguageSetting`, `isLocale`, `matchLocale`, `chromeLocaleFolder`), imported by `i18n/core` and `shared/settings` (no cycle) and by the Node scripts;
  - lazy catalogs: pages and service worker bundle English only (reference and fallback, `i18n/index.ts`); another locale is read on demand from the package, `assets/locales/<code>.json` (eager `import.meta.glob(…, { query: '?url' })` without en, readable name from `assetFileName` in `src/build/output-names.ts`; Rolldown merges byte-identical files, so two identical catalogs would share one file and `verify:build` checks each locale by content), with `fetch(new URL(url, import.meta.url))`, never a dynamic `import()` (forbidden in the Chrome module service worker). `loadLocale` is memoized per locale (failure: warn, English kept, retried on the next request); `applyLanguageSetting` is async (load, then `setLocale`; the last request wins). Invariant: the active locale always has its catalog registered (English until `initI18n`); `setLocale` stays synchronous and expects a loaded catalog (unit tests: `src/test/setup.ts` registers every catalog; e2e and screenshot frames preload their `locale` param, `scripts/screenshots/params.ts` › `loadedLocaleParam`, then other locales load lazily);
  - content scripts embed the `CONTENT_KEYS` in English only (`__SYNCKAI_CONTENT_CATALOGS__`) and ask the service worker for another locale (`GET_CONTENT_CATALOG` `{ locale }`, origin `content` → the `CONTENT_KEYS` of the loaded catalog, English for a missing key, `null` if unavailable; 5 s timeout; any failure → English, retried at the next need). Never requested at start (PERF-12): every shown text first awaits `ensureContentLanguage` (`i18n/content.ts`: settings re-read unless given, one request per locale and page, memoized by `loadLocale`), i.e. `watch-session` › `loadSettings` (end of episode, before any toast; `init` uses `readSettings`, no language), its unidentified-episode and already-synced toasts, and the no-playback shortcut toast in `start.ts`; the orphan toast (context invalidated) keeps the locale already loaded, else English; never a `storage.onChanged` listener there (PERF-03); content code (and `i18n/core`) reads settings through `getContentSettings` (`browser/storage/content-settings.ts`, only the fields it uses, normalized by `shared/content-settings.ts` › `normalizeContentSettings`, which `normalizeSettings` reuses), never `getSettings` / `normalizeSettings` (`architecture.test.ts`); no `tp` / `tpl` in content code (plural variants differ per locale, tested);
  - texts translated by the service worker (error and « introuvable » messages of `RESOLVE_PAGE_MEDIA`, `ApiError` messages) reach the screens already translated: on `onLocaleChange`, `ui/page-media-controller.ts` re-requests an `error` / `not-found` card, and the service worker, which does not follow the settings (`initI18n({ follow: false })`, no wake-up on every local write), re-reads the language before each piece of work that may produce text: `background.ts` › `languageReady` (`refreshLanguageSetting` in `i18n/core.ts`: one `storage.local.get('settings')`, catalog load memoized, then `languageSettled()`, last `applyLanguageSetting` applied) gates every message dispatch and, through `afterI18n`, the sync-queue and airing alarms and the job resumes; the commands and notification clicks produce no text and are not gated. Pages (popup, side panel, settings, import) keep follow mode. Texts already stored (*Activity* rows…) keep their language; carrying a key + params instead of text is the complete fix (not done);
  - plurals: variants `key_<category>` per `Intl.PluralRules` of the locale: required = categories selected for some integer 0..1000, plus `other`; allowed = the locale's categories (ja, zh, ko, vi, id: `_other` only; ru, uk, pl: `_one _few _many _other`; cs, ro: `_one _few _other`, cs `_many` allowed (decimals only); fr, es, it, pt: `_many` allowed). `tp` / `tpl(locale, …)` fall back to `_other`, then to English with English rules. `{count}` may be omitted only where the English `_one` omits it. Counts written in full words go through plurals (`time.daysAgo`, `airing.notification.group` since 2026-10-13); abbreviated ones (`min`, `h`, countdowns) stay `t()`. `npm run i18n:check [-- <codes>]` (`scripts/i18n-check.ts`, same rules as `src/i18n/locales.test.ts` through `src/i18n/catalog-check.ts`, plus informative warnings: English text ≤ 24 characters translated more than 1.6× longer);
  - browser language → locale (`matchLocale`): exact supported code wins (`pt-BR`, `es-419`…); zh: `Hant` script or TW / HK / MO region → zh-TW (an explicit `Hans` wins over the region), any other zh → zh-CN; es: no region or ES → es, any other region → es-419; pt (any region, PT included) → pt-BR; else the base language if supported (fr-CA → fr), else en; deprecated codes canonicalized (`in` → id);
  - picker names (`language-list.ts`, Intl.DisplayNames, no translation needed): zh-CN / zh-TW named through zh-Hans / zh-Hant (« 简体中文 » / « 繁體中文 »), es through es-ES (« Español de España » / « Español latinoamericano », distinct in every UI locale, tested); search field from 8 locales. `lowerFirst` uses `toLocaleLowerCase(locale)` (Turkish dotted / dotless i); `weekLocaleTag` compares base languages (ui es-419 + browser es-MX → es-MX);
  - adding a language: code in `LOCALES`; catalog `src/i18n/locales/<code>.json` (copy of `en.json` with the plural variants of the language, then translated; `npm run i18n:check -- <code>`); folder `public/_locales/<code, "-" → "_">/messages.json` (same messages as en, `extDescription` ≤ 132 characters; required by `scripts/browser-locales.test.ts` and `scripts/package.ts`); translator: term sheet `docs/i18n/glossary/<code>.md` first, then the catalog with the context notes; then an independent review logged in `docs/i18n/review/<code>.md`, and `npm run test:i18n-layout`; the Netflix import's « Show more » label of that language added only once verified (see Netflix history import).
